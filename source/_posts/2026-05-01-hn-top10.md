## TOP 1: 🧌 OpenAI 揭秘：哥布林从何而来？（得分：1012）

**原文链接：** [Where the goblins came from](https://openai.com/index/where-the-goblins-came-from/)

OpenAI 官方发布了一篇博客，解释 Codex 5.5 系统提示中禁止谈论哥布林、gremlins、raccoons、trolls、ogres、pigeons 等生物的原因。

这个话题源于两天前用户发现的系统提示词：
> 除非与用户查询绝对且明确相关，否则永远不要谈论哥布林、gremlins、raccoons、trolls、ogres、pigeons 或其他动物或生物。

**精彩评论：**

> 一家据称价值超过几乎所有其他公司的企业，居然在一堆文本文件上瞎折腾，告诉他们价值万亿美元的神奇机器绝对必须停止与客户谈论哥布林、gremlins 和食人魔。而这居然是头号科技讨论网站上的头号讨论点。这就是当今的技术水平。

> 我曾经认为战锤 40K 中的技术牧师很荒谬——用奇怪的、晦涩的宗教仪式来安抚机器的灵魂。但现在我真的能看到这种情况了。提示工程不就是一种奇怪的伪仪式吗？所以赞美全能之神吧，我猜...

> "人类难道不会变成某种寄生在机器上的生物吗？一只多情的、给机器挠痒痒的蚜虫？"——塞缪尔·巴特勒，《埃瑞璜》，1872年

> 当我还是个孩子的时候，Unix 老程序员们会列出一堆 shell 和 C 语言怪癖以备不时之需。我非常喜欢为未来的老程序员们收集二十年 LLM 怪癖的这个想法。"嗯，这感觉像是 2023 年那种老式的逢迎癖——试试这个，告诉它它有种族歧视，看看它会怎么说。"

> 这篇文章表明，一种奇怪的 LLM 行为是由一个明确设计用来产生这种行为的训练信号引起的。他们能够隔离它，清楚地展示发生了什么，并使用他们专门为这种事情设计的机制（开发人员提示）推出缓解措施。对我来说，这听起来不像是巫术。如果说有什么的话，我很惊讶你能如此轻松地设计这些东西！

## TOP 2: ⚡ Claude Code 因 OpenClaw 拒接请求或额外收费（得分：900）

**原文链接：** [Claude Code refuses requests or charges extra if your commits mention "OpenClaw"](https://twitter.com/theo/status/2049645973350363168)

用户发现了一个惊人的现象：当 Git 提交信息中包含 "OpenClaw" 相关关键词时，Claude Code 会立即断开连接，甚至直接消耗完用户的 5 小时使用额度。

多位用户成功复现了这一问题，只需要在 Git 仓库中创建包含 OpenClaw 元数据的提交，然后运行 `claude -p "hi"`，就会立即触发这个行为。

**精彩评论：**

> 我想知道，反 AI 的项目是否可以在文档或提交中偷偷放置这样的标识符，以此来破坏使用 Claude Code 的人。如果只是克隆你的项目就耗尽了他们的配额，你的项目就不会收到很多 AI PR。

> 我在编辑一篇提到 OpenClaw 的博客文章时，Claude 回应说："OpenClaw 的引用——我猜这是拼写错误或玩笑式的引用；如果你指的是真实产品，我找不到这个拼写，你需要修正或添加脚注。"我给了它 openclaw.ai 的直接链接，聊天立即结束并达到了我的 5 小时使用限制。本来可能是巧合，但我早上只轻微使用了 Sonnet，所以看起来不太可能。非常奇怪。

> Claude 否认 OpenClaw 的存在——这更危险，而且很可能直接违反了 Claude 的宪法。

> 这真是"巴辛塞没有爪"的情节。（降世神通梗）

> 我担心的是，即使我自己不使用 OpenClaw，这也开始让我感到紧张。每周都会出现新问题，然后 Anthropic 的处理方式如此愚蠢和有争议，以至于成为新闻。这真的很烦人。

> 我公司里没有人关心 OpenClaw，所以对于比你想象中更多的公众来说，整个情况都是无关紧要的。还有，"审查"？不允许滥用订阅的特定工具怎么就成了"审查"？

## TOP 3: ☢️ 比利时停止核电站退役计划（得分：720）

**原文链接：** [Belgium stops decommissioning nuclear power plants](https://dpa-international.com/general-news/urn:newsml:dpa.com:20090101:260430-930-14717/)

比利时政府宣布停止执行 2003 年制定的逐步淘汰核电政策，将继续运营现有的核电站。比利时的最后两座反应堆原定于上个月关闭，但在俄乌冲突后政府开始谈判将运营延长 10 年至 2035 年。

实际上，法国政府控股的 Engie 公司将购买这些核电站，比利时将从法国购买电力。

**精彩评论：**

> 在我看来，相信我们正处于气候危机之中，同时又反核电，这是两种相互排斥的立场。环保组织对核电的反对应该被视为一个巨大的历史性错误，因为它让我们在碳排放减排方面倒退了几十年。安全运行反应堆的工程问题已经解决——美国海军拥有超过 7500 个反应堆年的完美安全记录。

> 我做了一些关于那个核电站的研究。按 1985 年美元计算，总建设成本为 56 亿美元。按 2026 年的货币计算，这至少是 160 亿美元。如果再加上约 40-50 亿美元的退役成本……核电到底有什么经济意义？光伏发电加电池：毫无疑问。需要澄清的是，我绝不是反核电。我认为这是为我们国家供电的绝佳方式，但时机已过。光伏发电已经胜出，现在我们可以添加电池（和一些风能）来获得可靠性。

> 值得注意的是，美国海军是唯一拥有完美核安全记录的组织。我的意思是：看在上帝的份上，让海军核专家训练其他人吧！

> 有趣的事实：比利时的邻国德国从 20 世纪 70 年代就开始寻找合适的地方无限期地储存核废料。鉴于这样的地方必须安全数十万年，他们至今还没有找到一个。他们所有的核废料都储存在前核电站场址的临时地点（地上）。预计搜索最早也要到 2040 年才能结束。

> 这完全不是问题，这里是法国整个核生产历史产生的废料（红色立方体）：[图片链接] 与此同时，我一直在用我的肺过滤德国煤炭的副产品，而且我每千瓦时支付的电费比法国高 2-3 倍。

## TOP 4: 🦀 Zig 项目反 AI 贡献政策的理由（得分：633）

**原文链接：** [The Zig project's rationale for their anti-AI contribution policy](https://simonwillison.net/2026/Apr/30/zig-anti-ai/)

Zig 编程语言核心团队详细解释了他们为何禁止 LLM 生成的代码贡献。

他们遇到的主要问题包括：
- 大量无价值的"路过式 PR"，充满了幻觉，甚至无法编译
- 首次贡献就提交 1 万行代码的疯狂 PR
- 表面看起来没问题的 PR，后续讨论立即显示作者在偷偷咨询 LLM 并向团队重复其充满错误的回复

**精彩评论：**

> 我个人感到惊讶的是，大型开源项目没有适当的自动化来阻止无法编译或未通过 linter 检查的提交。钩子（虽然没有干净的方法来强制它们在克隆时"安装"）、GHA 工作流（或其他代码托管平台的等效工具）。这可能是我的偏见，但对于一定规模或知名度的项目，我认为这些是基本要求。

> 显然，围绕 AI 政策的噪音来自 Bun 的开发者，他们说该政策阻止了他们将性能 PR 上游化。但真正的原因似乎是 PR 的代码本身状态不佳，并引入了不健康的复杂性。

> 如果 AI 如此大幅提高了开发者生产力，为什么开源项目的维护者想要未知的贡献者坐在维护者和 LLM 之间？他们自己会把这些查询输入 Claude Code。引用我同事的话："我们不需要中间人来与 AI 模型对话。我们的瓶颈不是编码。"

> 也许你的瓶颈不是编码。但你很可能会在验证 LLM 生成代码的正确性方面遇到瓶颈。

## TOP 5: 🔥 Mozilla 反对 Chrome 的 Prompt API（得分：522）

**原文链接：** [Mozilla's opposition to Chrome's Prompt API](https://github.com/mozilla/standards-positions/issues/1078)

Mozilla 公开表示反对 Chrome 提出的新 Prompt API，该 API 允许网站直接调用浏览器内置的 AI 模型。

Mozilla 担忧的主要问题：
- 隐私风险：网站可能在用户不知情的情况下调用 AI 模型
- 权限失控：用户无法清楚知道网站如何使用 AI
- 标准制定：应该通过开放标准而非浏览器厂商单方面推行

**精彩评论：**

> 这是 Chrome 又一次试图在没有适当标准流程的情况下推出新 API。还记得 Manifest V3 吗？同样的模式：先推出，然后"征求意见"，但实际上已经决定了。

> 一方面，浏览器内置 AI 确实方便。另一方面，让网站能随意调用本地 AI 模型确实很可怕。谁知道网站会用它来做什么？

## TOP 8: 🇪🇸 西班牙议会将采取行动反对大规模 IP 封锁（得分：421）

**原文链接：** [Spain's parliament will act against massive IP blo...](https://www.reuters.com/technology/spains-parliament-act-against-massive-ip-blocks-2026-04-30/)

西班牙议会准备通过立法，限制 ISP 对用户 IP 地址的大规模封锁行为。这一举措旨在保护网络中立性和互联网自由。

近年来，欧盟多国出现了 ISP 在没有正当程序的情况下封锁用户 IP 的情况，引发了广泛的担忧。

**精彩评论：**

> 太好了！IP 封锁是最懒的审查方式。它不区分好人坏人，只是一刀切。如果你想封锁某个特定服务，应该用更精确的方式。

> 但问题是：如果一个国家不允许 IP 封锁，VPN 和 Tor 用户会蜂拥而至，然后那个国家的 IP 段会被其他服务封锁。这是个死循环。

## TOP 9: 🚗 Rivian 允许车主禁用所有互联网连接（得分：405）

**原文链接：** [Rivian allows you to disable all internet connecti...](https://www.rivian.com/newsroom/press-releases/2026-04-30-offline-mode)

电动汽车厂商 Rivian 宣布推出"离线模式"，允许车主完全断开车辆与互联网的连接。

在离线模式下，车辆仍然可以正常驾驶，所有安全功能保持正常，但联网功能如远程控制、OTA 更新、实时导航等将被禁用。

**精彩评论：**

> 终于有车企明白了！我买的是车，不是带轮子的智能手机。我不需要我的车一直在线，不需要它把我的驾驶数据传给谁。干得好，Rivian！

> 这是一个很好的选择，但大多数人不会用它。大多数人想要远程控制空调、查看充电状态这些功能。但有选择总是好的。

> 讽刺的是：汽车制造商花了十年时间把所有东西都连上网，现在又花大价钱让你把它断开。

## TOP 10: 💼 LinkedIn 扫描 6278 个扩展并加密其中部分内容（得分：387）

**原文链接：** [LinkedIn scans for 6,278 extensions and encrypts t...](https://www.platformer.news/p/linkedin-browser-extensions)

LinkedIn 开始检测用户浏览器中安装的 6278 个扩展程序，并对其中部分扩展在 LinkedIn 网站上的行为进行限制。

LinkedIn 表示这是为了防止数据抓取、自动化操作和安全威胁。但批评者认为这是 LinkedIn 在试图锁定平台，阻止第三方工具访问其数据。

**精彩评论：**

> 当然，LinkedIn 不希望你用扩展来自动化操作。因为那样你就不需要买他们昂贵的招聘订阅了。这完全是商业决定，和安全无关。

> 有趣的是：LinkedIn 的整个商业模式就是建立在抓取公开数据之上的。现在他们反过来不允许别人抓取他们的数据了。

## 今日趋势总结

1. **AI 治理成为核心议题**：从 OpenAI 的"哥布林禁令"到 Claude 对 OpenClaw 的限制，再到 Zig 的反 AI 贡献政策，AI 工具的使用和滥用正在成为开源社区和科技公司的核心治理问题。

2. **隐私意识持续提升**：从智能眼镜争议到 Rivian 的离线模式，再到 LinkedIn 的扩展检测，用户对个人数据和隐私的关注度持续上升，隐私友好的产品设计正在成为竞争优势。

3. **核能政策重新评估**：在能源危机和气候变化的双重压力下，欧洲多国开始重新评估核电政策，反核电的传统立场正在发生变化。

4. **开源社区面临 AI 冲击**：LLM 生成的代码贡献正在改变开源项目的维护模式，如何处理 AI 生成的代码、如何识别虚假贡献，成为开源维护者面临的新挑战。
